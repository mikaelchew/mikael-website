# mikaelchew.com redesign: The Strategist's Map 兵法圖

**Date:** 2026-10-01 · **Status:** draft for Mikael's review · **Approved direction:** prototype `redesign/strategist-map/index.html` (Design 3)

---

## 1. Goal and success criteria

Rebuild the whole site (English pages and the generated `/zh/` mirror) in the approved Strategist's Map world, ready **before the ebook launch on 20 October 2026**, without breaking anything the launch depends on.

The redesign is finished when all of these are true:

1. **Every page** listed in §3 is rebuilt in the new world, in English and Chinese, with no page left on the old stylesheet.
2. **Nothing the launch depends on regresses:**
   - the Billplz checkout and the Apps Script delivery;
   - all Kit forms, each with its correct form ID and tag;
   - the Formspree contact form;
   - every GA4 event that exists today (§8).

   Each of these is tested end to end on the redesign branch before go-live.
3. **Phone speed:**
   - first screen (LCP) under 2.5s on a throttled mid-range phone, on the homepage and the book page;
   - CLS under 0.1 on every page;
   - verified with a Chrome DevTools trace at mobile size.
4. **Accessibility:** WCAG 2.2 AA contrast, keyboard access to every action, a correct `lang` on all Chinese content, a full `prefers-reduced-motion` path, and a minimum of 15px for any text a reader is expected to read.
5. **Facts:** every book fact on the site matches the manuscript and `BOOK_FACTS_ALIGNMENT.md`, with a final proofread pass.
6. **Design gate:** the Impeccable detector is run on every changed page, and an independent finish review returns a "ship" verdict.
7. **Approval and record:** Mikael approves the redesign on desktop and on his own phone, from a private preview link, before it replaces the live site. `DESIGN.md` records the finished system.

## 2. Non-goals

- **No framework, no npm, no build pipeline in CI.** The site stays hand-written static HTML/CSS/JS on GitHub Pages. The existing Python scripts (`build_zh.py`, `build_chapter.py`) remain the only generators, plus one new font-subset script (§7.3).
- **No change** to the checkout backend (`book-delivery/apps-script.gs`), the Kit account, the Billplz collection or the scorecard backend.
- **No new copy claims.** Copy is carried over and adapted to the new layout. New lines are limited to structural copy (headings, labels, calls to action) in Mikael's voice. Nothing invented: no endorsements, no reader reviews, no stars, no sales figures.
- **No light/dark theme switch.** The new world is one designed look: a dark map table with a beige "map back" band.

## 4. The design system

The world is the one the prototype established: the strategist's table.

### 4.1 Colour

| Token | Value | Use |
|---|---|---|
| `--table` | `#22303A` | Page ground: the map table |
| `--table-deep` | `#19242C` | Cards, panels |
| `--acetate` | `#F2F2EE` | Primary text on the table |
| `--mute` | `#B9C4C0` | Secondary text (7:1 on the table) |
| `--contour` | `#B6C4BE` | Contour lines, map labels |
| `--red` | `#C0392B` | **The one ink**, as fills only: the route, seals, primary buttons |
| `--red-lit` | `#F0705F` | Red used as text on the table (passes 4.5:1) |
| `--red-text` | `#A93226` | Red used as text on paper |
| `--paper` | `#F5F0E8` | Brand beige: the "back of the map" band and reading surfaces |
| `--ink` | `#1A1A1A` | Text on paper |

Rules:
- **Red does one job per screen:** the route, the seal, or the single primary action.
- **No other accent colours.** The green WhatsApp gradient on the current site is removed.

### 4.2 Typography

- **Latin:** Overpass at 400 / 600 / 800 / 900, self-hosted as woff2. Display sizes come from `clamp()`. Body text is 18–20px. Nothing a reader is expected to read goes below 15px.
- **Chinese display:** Noto Serif TC at 600 / 900, self-hosted as **a subset** containing only the characters used in display elements (§7.3). It covers 不戰而勝, the vertical legends, region names, chapter titles and seals.
- **Chinese body text** on `/zh/` pages uses the reader's system CJK font: PingFang TC on Apple devices, Noto Sans CJK on Android, Microsoft JhengHei on Windows. Full Chinese web fonts weigh megabytes, and system Chinese fonts are already good.
- **Tabular numerals** for every price, date and count.

### 4.3 Components

Each component is defined once in a new `css/site.css`. Its markup patterns are documented in `DESIGN.md` at the finish.

- **Top bar:** the 周俊德 / MIKAEL CHEW brand, plus six bilingual nav items: The Book 著作, About 關於, Writing 專欄, Speaking 演講, Work With Me 合作, and 中文 / English. On phones, The Book and the language link stay visible and the rest go into a full-screen menu.
- **Buttons:**
  - primary: red fill, white text;
  - secondary: an acetate outline.
  - Both have a press state (scale .97, 120ms).
- **Seal:** the red chop seal (an SVG symbol with the ink filter). It marks status only:
  - 十月上市, "on sale in October", before launch;
  - 已上市, "on sale now", from launch day;
  - 免費試讀, "free to read", on Chapter 1.
- **Recon print:** a light-on-dark halftone of a real photo, generated by `redesign/halftone2.py`. Each print carries its provenance (source photo and script) in `images/print/README.md`.
- **Briefing card:** a chapter or story card with the number, English title, Chinese title and one line. It has a hairline border; no thick coloured bars.
- **Map back band:** a beige section with faint contour lines, used for forms and next steps.
- **Forms:** one field plus a button. On submit they show an inline confirmation instead of opening a new tab (§8.2).
- **Vertical legend:** Ming-style vertical text in red, used for 不戰而勝 and for the Chinese titles of key pages.

### 4.4 Motion

This is the language the motion review set. Arriving motion uses `cubic-bezier(.23,1,.32,1)`, on-screen moves use `cubic-bezier(.77,0,.175,1)`, and physical contact (seals only) uses `cubic-bezier(.55,0,1,.45)`.

- **Signature moment:** the homepage route. It halts at each chapter, advances as you scroll, and ends at the launch date (§5). It is the only scroll-driven animation on the site.
- **Supporting motion, three pieces in total:**
  - the button press;
  - the dossier lift on hover, on mouse devices only;
  - the seal stamp, played once when a seal first appears in view, gated on the image having loaded.
- **Never animated:** first-screen headlines, stat numbers (no count-up), testimonials, photos (no Ken Burns, no parallax), navigation, forms. There is no section-by-section "fade up on scroll" anywhere. The old site's `.fade-in` system is retired.
- **Reduced motion:** all motion is off. The map shows the whole campaign, drawn, with every position marked, and every panel visible in normal page order.

## 7. Bilingual and font build

### 7.1 Chinese pages

`build_zh.py` keeps working exactly as today: it swaps `data-en` / `data-zh`, rewrites links and sets `lang`.

The rebuild needs two new behaviours in the script:
- Elements carrying `data-zh-only` (for example the vertical legends) are left untouched, so they read the same in both languages.
- The language link in the top bar points to the equivalent page in the other language. Today a client-side toggle does this job, and it is removed.

### 7.2 Language toggle

The current site translates pages in the browser and remembers the choice in `localStorage`. The redesign replaces that with plain links between the baked pages: English to `/zh/…` and back. That's simpler, crawlable, and it works without JavaScript.

The `language_toggle` GA4 event is kept, fired on that link.

### 7.3 Fonts

A new script, `build_fonts.py`, uses fontTools `pyftsubset`. fontTools and brotli are **not** installed for system Python today (checked 2026-10-01). They need a one-time `/usr/bin/python3 -m pip install --user fonttools brotli`, the same pattern as `lxml`, and that install step is added to PROJECT_HANDOFF.md's migration checklist.

- It collects every Chinese character inside elements marked with the `cjk-display` class across the English and Chinese pages, and writes the Noto Serif TC 600/900 subset woff2 files to `vendor/fonts/`.
- Run order after any copy change: `build_chapter.py`, then `build_zh.py`, then `build_fonts.py`.
- Overpass is shipped as a Latin subset woff2.

## 9. The launch-day switch (20 October)

Today the switch is a hand edit across several places. The redesign makes it one flag.

- `<html data-phase="prelaunch">` changes to `"launched"` on every page, through a single line in `js/site.js` and a matching value that `build_zh.py` carries over to the Chinese pages.
- **Prelaunch:** the 十月上市 seal; "on sale 20 October"; **Read Chapter 1 free** is the primary action; the launch-list forms are visible; `#buy` stays hidden.
- **Launched:** the 已上市 seal; the order box shows **Buy RM 29.90** and Kindle; `#buy` is visible and becomes the primary action; the launch-list forms are replaced by the print waitlist and the newsletter; the homepage finale offers Buy plus Read Chapter 1.
- **Still needed from Mikael before 20 October:** the Amazon Kindle URL (`#AMAZON_URL_PENDING`).
- **Rehearsal:** the switch is tested on the preview link before 20 October. Launch day is then a one-line change plus `build_zh.py`.

## 10. Accessibility

- Skip link on every page. Real `h1` → `h2` → `h3` order. `lang` correct on every Chinese fragment.
- Keyboard: every waypoint has a keyboard equivalent (the rail and the chapter list). Hidden panels are `inert`. Visible focus rings.
- Live regions only where they help (form confirmations). The chapter briefings are not announced on every scroll.
- Contrast is AA for all text. The red text tokens in §4.1 are already chosen to pass.
- `prefers-reduced-motion` is fully supported (§4.4), and `prefers-reduced-transparency` is honoured (there is no transparency that carries meaning).

## 11. How it gets built and shipped

1. **Branch.** All work happens on `redesign/strategist-map` in a git worktree. `main` stays live and untouched, so other sessions' fixes keep shipping. Pushing `main` publishes, so nothing from the branch reaches `main` without Mikael's sign-off.
2. **Preview.** GitHub Pages serves only `main`, so the branch needs its own preview. Two options:
   - a private Vercel preview of the branch, as a static deploy with no build step;
   - Mikael testing on his phone over the local network.

   Which one is decided in the plan, with Mikael.
3. **Order:**
   1. Shared shell: `css/site.css`, `js/site.js`, top bar, footer, fonts, the `build_zh.py` changes.
   2. The homepage.
   3. The book page, including the checkout and launch switch.
   4. Chapter 1.
   5. The thank-you page.
   6. About, Speaking, Work With Me, Contact, Concepts.
   7. The blog index and the 25 posts.
   8. Legal pages, 404, scorecard.

   **Cut line:** if time runs short, steps 1–5 ship before launch and the remaining pages move to the new shell in week 1 after launch. They keep working on the old stylesheet until then, because the new CSS is a separate file.
4. **Verify** after each page: Impeccable detect, screenshots at desktop and phone, the integration tests from §8, and a DevTools mobile trace for pages whose first screen changes.
5. **Finish:** an independent finish review, DESIGN.md recorded, Mikael's sign-off on the preview link, then merge to `main` (which publishes). Merge no later than **17 October**, to leave three days of live checking before launch.
6. **Old code:** `css/style.css` and the old `js/main.js` features are retired only after every page has moved. `vendor/fontawesome` is removed if no page still uses it.

## 12. Risks

| Risk | Mitigation |
|---|---|
| 19 days is tight for the whole site | The cut line in §11.3. The launch-critical pages come first. |
| The checkout regresses during launch week | The checkout is tested on the preview with a real or sandbox payment, and the code path stays the same `data-endpoint` handler. |
| Older or low-end Android phones struggle with the map | Smoothness was measured on a throttled phone profile; real-device testing on the preview. Fallback: below a device-memory or frame-time threshold, the map renders in its static "whole campaign" form. |
| Chinese pages look different because of system fonts | Display text uses the self-hosted Ming face; only body text uses system fonts. Checked on iPhone and Android. |
| Parallel sessions edit the same pages on `main` | Rebase the branch on `main` before merge. Content edits made on `main` during the rebuild are carried over by hand, with a diff check of the copy. |
| Fact drift | The chapter data lives in one file used by both the homepage and the book page. A final proofread against `BOOK_FACTS_ALIGNMENT.md` happens before merge. |
